## Findings and corrections in the continuation

1. Explicit null pull cursor previously bypassed SQL three-valued bounds validation, yielding an unusable/null checkpoint. It now returns validation HTTP 400; omitted cursor remains zero. Tests cover omitted/null/malformed/empty/caught-up pages alongside existing retry, fixed-watermark, byte bounds, owner isolation and delayed commits.
2. Missing entity conflict details lacked an ID. All unavailable lookup paths now include the requested kind/id with null state, while stale/deleted paths include the canonical row and ID. Foreign identities do not disclose their existence. Missing dependencies include their operation ID. Exact conflict receipts remain replayable.
3. Deleted groups now return their authoritative tombstone as a conflict rather than a generic invalid relationship result. A genuinely mismatched live group/category remains validation.
4. Parent deletion previously bounded assigned tasks and final results but could iterate arbitrarily many groups/series before rejecting. A bounded preflight now rejects oversized combined cascades before dependent writes. The rollback-only 2,000-group test proves no partial group tombstones escape.
5. Previously unrun daily/weekly/monthly overflow cases are now exercised, with additional command-level tests proving task/event/feed/receipt behavior stays atomic when the next occurrence exceeds year 9999.

No product architecture replacement was required. The old already_completed special case is explicitly a structured conflict, preserving the original event/successor while giving Phase 8 an actionable competing-intent result. Read wrappers use restricted SECURITY DEFINER so internal feed/receipt tables remain inaccessible; they still execute forced RLS under the constrained role.

## Release blockers and follow-up

The historical Docker blocker is resolved. Native PostgreSQL 17.11, managed roles/default grants, Kong gateway and GoTrue-issued AAL1/AAL2 token access are now tested. The 18-assertion pgTAP companion also runs natively. Product enrollment UI, registration, recovery, refresh/logout and account-cache lifecycle remain Phase 7; these fixture flows do not implement them.

Inspect cloud security advisors and final object/function/default privileges on the configured full stack; ensure executor can neither be assumed by API roles nor bypass RLS. Fresh native application and forward corrections were rehearsed on the verified-empty disposable stack; repeat on a separately authorized deployment target. There is no deployed prior cloud schema to upgrade; blank schema application and transactional failed-forward-DDL rollback are tested. No migration touched IndexedDB or user data.

Future client sync must freeze dependent server revisions before first send, retain commands after application errors, apply acknowledgement/page state atomically, avoid jumping its pull cursor to an acknowledgement watermark, reject late identity responses and never upload synthetic workspace records. PostgreSQL name uniqueness uses NFC plus database lower/collation; JavaScript default Unicode lowercase can differ for some characters, so a server name validation may reject a locally accepted name. No record is discarded; Phase 8 must retain that rejection. Verify configured locale and representative names on the native stack. Account erasure, storage retention capacity, rate limits, backups, recovery policy, device loss and independent security review remain release work. No claim of end-to-end encryption, instant offline revocation or full browser/device certification is made.

## Native certification findings and remediation

The native run exposed a managed-environment assumption missing from the standalone fixture. Supabase postgres has auth schema USAGE without grant option; granting it to a custom executor silently has no effect. Valid AAL2 commands consequently failed closed with permission errors. Original migrations 001–004 remain unchanged. Migration 005 adds private current_user_id/current_aal bridges following Supabase's documented narrow Auth definer pattern and switches executor policies/operations to them. Migration 006 handles compact Auth-call spelling in the cascade preflight. Both public task-data mutation/read RPCs and their helpers continue to enforce owner/AAL2 under the restricted executor; the two bridge bodies alone run as postgres and only call native accessors. API roles cannot execute them or use their schema, they take no parameters, and they cannot query task data. No Auth schema grant, privileged API membership or RLS bypass was introduced. This is a documented exception to the earlier all-private-helpers-invoker statement.

The native default ACL inspection found residual Dxtm table permissions (TRUNCATE, REFERENCES, TRIGGER, MAINTAIN) and sequence UPDATE for anon/authenticated/service_role. Existing business/protocol objects already had all direct privileges revoked, so no observed task-data bypass existed. Migration 007 removes those defaults for future migration/executor-created objects. A rollback-only public table/sequence probe confirms all three API roles receive no implicit privileges. Platform administration defaults are not modified; creating future business objects under platform roles would require renewed review.

Final tests assert three public SECURITY DEFINER RPCs owned by the NOLOGIN/NOINHERIT/NOBYPASSRLS executor, two private argument-free Auth bridges owned by postgres, fixed empty search_path, no API role membership in executor, no executor inheritance from authenticated, no direct native auth schema access, and no remaining direct Auth calls in executor functions. The REST exposed schema is public only; private helpers/feeds/receipts cannot be reached directly. Native denial tests use actual signed password/MFA sessions; fabricated JWTs test rejection only. The original four migration hashes match the pre-certification files.

Local native certification passes. It does not test hosted resources or certify a production deployment. Rate controls, retention capacity, recovery operations, full account/session UI and client multi-device reconciliation remain later release work.
